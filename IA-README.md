# Information architecture (IA)

This is a separate note from the project's own `README.md` (which documents
the clone itself, fidelity numbers, and how to run it). This one documents
the IA artifacts added alongside it.

**Reference-clone notice**: this codebase is a local reference clone of
Mirai Labs' live marketing site — content, branding and design belong
to Mirai Labs. The sibling `design-repo/registry.manifest.json`
(`sourceProject` field) already states this; this IA repeats it once here
(`ia.json`'s `meta.source`) so the IA doesn't read as documentation of an
original site.

## What's generated vs. hand-edited

- **`ia.json`** — hand-edited. The only file to touch when routes, templates,
  or sections change.
- **`IA.md`**, **`matrix.csv`** — generated by `build.mjs` from `ia.json`.
  Never hand-edit these; rerun the build instead.
- **`build.mjs`**, **`validate.mjs`** — copied as-is from the `ia-builder`
  skill, generic and driven entirely by `ia.json`.

To re-run after editing `ia.json`:

```bash
node validate.mjs && node build.mjs
```

## How this pairs with `design-repo/`

`design-repo/templates/templates.json` and `design-repo/sections/*.json`
already encode this project's real route→template mapping and section
inventory (built and verified earlier this session, with file citations).
`ia.json`'s `templates` block reuses the same route groupings as
`design-repo` — including collapsing `/privacy-policy` + `/terms-of-use` into
one `template.legal` (same source file, same rendered shape via a `kind`
prop) and `/blog` + `/blog/:slug` into two separate templates
(`template.blog-index` / `template.blog-post` — same source file,
genuinely different section composition). `ia.json`'s section ids/naming
differ from `design-repo`'s (the IA is a structure map for humans; the
design-repo is a machine-validated content contract), but no real page is
classified as two templates in one artifact and one template in the other.

## Real findings from `validate.mjs` / `build.mjs`

- **14 routes across 13 templates, 44 unique sections** (`node validate.mjs`
  reports 0 undefined-section references and 0 defined-but-unused sections —
  full referential integrity between `templates[].sections` and the
  `sections` block).
- **9 of the 44 sections are shared across templates; 35 are single-use**
  (`node build.mjs`'s "9 shared sections · 35 page-local" line). The 9 shared
  ones are `shell.navbar` and `shell.footer` (all 13 templates / 14 routes),
  plus `hero.product`, `proof.bench-strip`, `proof.model-cards`,
  `content.perfect-for`, `content.faq`, `cta.closing-band`, and
  `hero.page-header-simple` (each shared by exactly 2 templates). Everything
  else — all of the homepage's unique sections, both product pages'
  page-specific feature blocks, and every content page's body — is real,
  correctly page-local content with no second caller, so per the skill's own
  guidance it should stay page-local rather than get prematurely extracted
  into a shared component.
- **The largest 3 templates (Legal, Home, Product — toolkit) account for only
  4 of 14 routes (29%)** — most of this site's route count comes from having
  many distinct one-off page shapes (About, Careers, Metrics, Local models,
  Chat for Mac, Contact, 404, blog index/post) rather than from a large
  patterned collection; there is no paginated/numbered route family in this
  project at all, which is why every template here uses a literal `routes`
  array instead of `routePattern`/`routeRange`.
- `validate.mjs`'s scope-prose-vs-computed-count check flagged 4
  informational (non-failing) notes — all real, not typos: `shell.navbar` and
  `shell.footer`'s scope text ("14 routes (13 real + 404)") contains the
  numbers 13 and 404 in addition to 14, which the checker's number extraction
  picks up separately; `proof.metrics-chart-panel`'s scope correctly notes 3
  *instances per page* on 1 route, and `content.about-prose-block`'s scope
  correctly notes 5-6 *instances per page* on 1 route — both are real repeat
  counts, distinct from `routeCount`, and should not be "corrected" to match
  it.
